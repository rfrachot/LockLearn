# P1 — Content core, data supply chain and signed starter content

> Detailed work packages for `MASTER_PLAN.md`. `SPEC_V1.md` remains normative.

## P1.1 — Canonical content domain model

**Spec:** §4, §5, §6, §7, §8, §16, §75, §133

### Deliverables

- [x] Implement stable typed representations for Source/Dataset/Concept/Term/LearningItem/Facet/CardDefinition.
- [x] Keep Concept source-native; prohibit automatic cross-source semantic merges.
- [x] Define stable IDs/card identity including facet_id/card_definition_id and explicit migration mappings.

### Exit criteria

- [x] Core has no Japanese-specific branching.
- [x] Progress identity can survive dataset updates.
- [x] Cross-source alignment is explicit and confidence-bearing, not inferred from gloss similarity.

## P1.2 — Dataset package contract, signatures and hostile-archive handling

**Spec:** §74.5, §74.5.1, §74.9, §77, §82

### Deliverables

- [x] Define strict versioned ZIP manifest, signed payload membership and distinct package/content/dataset versions.
- [x] Verify exact manifest bytes with Ed25519 public-key IDs, validity, deprecation and revocation semantics.
- [x] Stream payload hashes and apply the existing source/license registries for official-package policy.
- [x] Reject hostile paths/types/collisions/bombs before trust or extraction; validate staged SQLite read-only with `integrity_check`.
- [x] Document why the ZIP checksum is external release metadata rather than a self-referential manifest field.

### Exit criteria

- [x] Every payload is transitively authenticated by the signed manifest.
- [x] Unknown, revoked, malformed, tampered and policy-incompatible packages fail closed.
- [x] A synthetic minimal SQLite package passes without defining the future content schema.

## P1.6 — content.db schema, generations and stable merge

**Spec:** §67, §68, §74.9, §75

### Deliverables

- [ ] Create content schema/indexes/pre-aggregates and immutable generation metadata.
- [ ] Build content.next.db from one prebuilt package at a time; validate then atomically switch active generation.
- [ ] Drain old readers and retain previous generation for rollback.

### Exit criteria
