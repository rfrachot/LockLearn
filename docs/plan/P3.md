Implementation note: progress undo appends a non-retrieval compensating

independent rebuild from ReviewEvents and excludes undone responses.
ADR-0033 records the boundaries.

## P3.13 — Basic statistics and metacognitive calibration backend

**Status:** implementation complete; verification pending.

**Spec:** §57, §58

### Deliverables
- [x] Build stats_daily projection and core due/verified accuracy/retention/new-review-relearning/leech metrics.
- [x] Compute self-assessed-known vs later verified performance and confusion views.
- [x] Implement streak semantics with due-queue goal, grace day and neutral no-due days.

### Exit criteria
- [x] Dashboard metrics distinguish exposure/self-assessment from verified retrieval.
- [x] Historical local dates are not rewritten when timezone changes.

Implementation note: `stats_daily` is now maintained on every committed
ReviewEvent using the same per-day aggregation primitive as the P3.12 repair
rebuild, and undo recalculates affected historical days. `locklearn/stats/get`
returns due-through-local-midnight counts, current state counts, latest trusted
verified retention, recent verified accuracy, secondary time-decayed mastery,
metacognitive calibration, frequent confusions, daily aggregates and streak
state. Calibration counts distinct cards declared known through either
`known_already` audit or positive post-retrieval self-assessment, then inspects
the first later trusted verified retrieval. The default streak goal is 80% of
the reconstructed daily due queue, minimum one card, with one grace day; no-due
days are neutral. Historical event/stats timezone names drive historical day
boundaries. ADR-0034 records the semantics. Notification receptivity remains P4
runtime scope and is not fabricated here. Final PASS remains contingent on the
full repository gate.
