# P6 — V1 hardening, lifecycle, security, docs and release

> Detailed work packages for `MASTER_PLAN.md`. `SPEC_V1.md` remains normative.

## P6.1 — Database/config/content migrations and recovery

**Spec:** §72, §73, §115

### Deliverables
- [ ] Implement sequential transactional state migrations with pre-migration coherent backup.
- [ ] Keep Config Entry, state schema and content/dataset schema migration mechanisms distinct.
- [ ] Test old-supported-release → current paths and failure recovery.

### Exit criteria
- [ ] Migration failure never silently corrupts the only user-state copy.

## P6.2 — Backup hooks, unload/reload and uninstall/recovery UX

**Spec:** §62.1, §70, §84.1

### Deliverables
- [ ] Finalize backup write quiescence/checkpoint/snapshot/resume with timeout.
- [ ] Exclude/rebuild content cache where supported and surface policy/size.
- [ ] Offer keep state/delete state/delete cache/delete everything on uninstall.
- [ ] Handle integrity failure by read-only + Repairs + recovery options.

### Exit criteria
- [ ] No raw active-WAL copy is used as backup.
- [ ] No state purge is silent.

## P6.3 — Repairs and diagnostics

**Spec:** §62.1, §83

### Deliverables
- [ ] Create Repairs for dataset obsolete/signature invalid, target unresolved, migration/integrity failure, infeasible scheduler and backup-cache anomaly.
- [ ] Implement redacted diagnostics with versions/counts/status/errors only.

### Exit criteria
- [ ] Diagnostics contain no profile names, learned content, responses or private stats.

## P6.4 — Secure export/import and data deletion

**Spec:** §65.1, §82, §84, §85, §86

### Deliverables
- [ ] Generate versioned profile exports in private temp storage and serve authenticated/signed ephemeral URL.
- [ ] Dry-run import mappings and reuse hostile-archive protections.
- [ ] Implement archive vs permanent profile deletion and complete personal-data cascade.
- [ ] Preserve history references/tombstones when pack/dataset content disappears.

### Exit criteria
- [ ] Export/private assets are never public static files.
- [ ] Permanent delete removes required user state after strong confirmation.

## P6.5 — HA entity/sensor privacy contract and optional integration boundary

**Spec:** §59, §60, §87, §130

### Deliverables
- [ ] Define stable UUID unique_id/logical-device model, opt-in privacy rules, debounce/Recorder guidance and valid state_class semantics.
- [ ] Ensure V1 never exposes learning content/private details through entities by default.
- [ ] Do not make optional sensor implementation a 1.0 blocker; if implemented before 1.0, it must obey this contract.

### Exit criteria
- [ ] A 1.0 release may ship no optional sensors and still satisfy the spec.
- [ ] Any shipped entity is opt-in, aggregate-only and Recorder-conscious.

## P6.6 — Security hardening and threat-model tests

**Spec:** §65.1, §82, §116, §117

### Deliverables
- [ ] Threat-test XSS/rich text/SVG, archive extraction, SQL filter schemas, replay, ACL bypass and private asset leakage.
- [ ] Sanitize SVG at build; strip scripts/event handlers/external refs/foreignObject.
- [ ] Parameterize SQL and validate pack filters via strict schema/allowlist.

### Exit criteria
- [ ] Security invariants have automated regression tests and documented threat model.

## P6.7 — Performance, scale and storage-budget validation
