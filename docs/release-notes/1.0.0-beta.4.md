# LockLearn 1.0.0-beta.4 — release notes

Status: candidate prepared locally only. No tag, GitHub Release or HACS
publication has been created.

## Highlights

- Closed-book exam sessions with representative frozen MCQ questions, private
  answer keys, irreversible answers, pause/resume, final score and error review.
- Neutral `exam_retrieval` audit events with a 12-hour notification cooldown;
  exam answers do not promote SRS boxes directly.
- Durable, crash-recoverable Home Assistant event outbox for mobile answers,
  with replay-safe delivery and documented at-least-once semantics.
- No-dead-end learning and quiz readiness: effective blockers, verified quick
  calibration, one-shot reminders, safe known-already reversal and retry-safe
  answer submission.
- Companion quiz hardening, Home Assistant presence-trigger lifecycle fixes and
  the patched frontend `source-map-js` dependency.

## Compatibility and migration

- HACS/Home Assistant floor: `2025.2.0`; full minimum lane: `2025.2.5`.
- Full current harness: `2026.9.3`; latest-stable smoke: `2026.9.4`.
- State schema is v6. Existing v0.0.2 state upgrades sequentially through
  v1 → v2 → v3 → v4 → v5 → v6. No downgrade is supported.
- Content schema remains v2 with the signed bundled Japanese Starter dataset.
- Frontend protocol remains v3.

## Upgrade and rollback

Create and verify a complete Home Assistant backup before installing beta.4.
Install it through HACS only after the exact tag is published. If rollback is
needed after a schema migration, restore the pre-upgrade backup or move forward
to a compatible fix; do not install an older integration over a migrated
`state.db` and do not rewrite the database manually.

## Remaining acceptance gates

The candidate still requires explicit maintainer approval, publication of the
tag/release, and physical Companion checks on Android and iPadOS. Real HA field
qualification must be repeated against the beta.4 payload after installation.
